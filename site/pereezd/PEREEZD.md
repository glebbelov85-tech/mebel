# Переезд витрин на отдельный адрес

Цель: витрины открываются по нейтральной ссылке без имени владельца, например
`https://vitrina-mastera.github.io/krasnodar/klient/` вместо `https://glebbelov85-tech.github.io/mebel/krasnodar/klient/`.
Старые ссылки продолжают работать: после переезда они сами открывают ту же страницу на новом адресе.

## Что переезжает

| На старом сайте | На новом | Что это |
|---|---|---|
| `mebel/vitriny/` | `vitriny/` | выбор витрины |
| `mebel/vitrina/` (+ `redaktor/`, `puteshestvie/`, `dizajn/`, `dizajn2/`) | `vitrina/` | витрина мастера, Мастерская, путешествие, оформления |
| `mebel/krasnodar/` (все подстраницы, `enc/`) | `krasnodar/` | закрытая витрина по пин-коду |
| `mebel/shared/site.js`, `site.css`, `golos.js`, `version.json` | то же | навигация, голос, пометка обновления |

Не переезжают: инструменты мастера (Конструктор, Блокнот, калькулятор, конфигуратор, КП, раскрой, учёт).
В витрине кнопка "Собрать шкаф в 3D" вела в конфигуратор - на новом сайте она скрыта.

Все ссылки внутри витрин относительные, поэтому структура папок та же, меняется только начало адреса.

## Как устроено (уже сделано)

- `site/tools/vitriny-vynos.py ПАПКА` - собирает сайт витрин для нового репозитория из тех же исходников
  (`site/vitrina`, `site/vitriny`, `site/krasnodar`, `site/shared`): обычная сборка во временную папку, из неё
  берутся витрины, правки под сайт без инструментов (верх навигации - "Витрины", без кнопки конфигуратора),
  README, 404, корневая страница. Сам проверяет битые ссылки и что нигде нет старого адреса и имени.
  Файлы `krasnodar/enc/`, которые уже лежат в новом репозитории, но которых нет в исходниках, не удаляет.
- `site/tools/pereezd_ssylki.py` + хук в конце `site/build.py` - переадресации со старого адреса.
  Выключены, пока нет файла `site/pereezd.json`.
- `site/pereezd/README-novogo-repo.md` - README нового репозитория (скрипт кладёт его как `README.md`).

Исходники витрин на время пробы остаются здесь - одно место правок, новое репо получает готовую сборку.

## Шаги

### 1. Организация (делает Александр, 3 минуты)
1. https://github.com/account/organizations/new?plan=free (бесплатный план Free).
2. Имя организации: `vitrina-mastera` (на 23.11.2026 свободно). Запасные: `masterskaya-vitrin`, `mebel-vitrina`.
   Имя будет в адресе: `https://vitrina-mastera.github.io/`.
3. Почта - своя, "My personal account". Остальное пропустить.

### 2. Репозиторий (делает Александр, 2 минуты)
1. В организации: New repository, имя ровно `vitrina-mastera.github.io` (тогда сайт открывается с корня, без лишнего слова).
   Public (бесплатный Pages работает только с публичными), галочку "Add a README" не ставить.
2. Дать Claude доступ: https://github.com/apps/claude/installations/select_target - выбрать организацию,
   "Only select repositories" - этот репозиторий. После этого Claude подключит репо к проекту.

### 3. Пробная публикация (Claude)
1. `python3 site/tools/vitriny-vynos.py <клон нового репо>`, коммит, push в `main`.
2. Включить Pages (Settings - Pages - Deploy from a branch, `main`, `/ (root)`). Через прокси сессии это закрыто,
   нажимает Александр (одна кнопка), как было с основным сайтом.
3. Проверка встроенным браузером на компьютере Александра: телефон и компьютер, все витрины, вход по пин-коду,
   Мастерская, ссылки `#rabota=`, видео, 404. Старый сайт в это время не меняется.

На этом этапе обе ссылки работают параллельно. Новое репо - зеркало: правки делаются как обычно в основном репо,
а действие `.github/workflows/obnovlenie-vitrin.yml` в новом репо (копия - `site/pereezd/obnovlenie-vitrin.yml`)
каждые 10 минут забирает новый коммит, собирает витрины и публикует. Сделано 2026-11-23, адрес работает:
https://vitrina-mastera.github.io/ (Pages включился сам).

Расписание GitHub на деле не срабатывало, поэтому основной путь (2026-11-23) - действие в этом репо
`.github/workflows/vitriny-novyj-adres.yml`: при каждом push в main с изменениями в `site/` или `src/`
(наши PR и публикации мастера из Мастерской) собирает витрины и пушит в новое репо токеном из секрета.
Нужно один раз (делает Александр): личный токен fine-grained (владелец ресурса vitrina-mastera, только репо
vitrina-mastera.github.io, Contents: Read and write) - секретом `VITRINY_TOKEN` в этом репо
(Settings - Secrets and variables - Actions). Вместо токена можно ключ развёртывания: `VITRINY_DEPLOY_KEY`.
Без секрета действие ничего не публикует и не падает. Расписание в новом репо осталось запасным.

### 4. Переключение (Claude, по команде Александра)
Перед этим:
- мастер Краснодара публикует всё, что начал в Мастерской (черновик в браузере привязан к адресу и на новом не виден);
- если включена самостоятельная публикация мастера (коммит через GitHub API, настройки в `enc/p.json`) - пройти
  настройку заново на новый репозиторий с новым токеном.

Переключение:
1. Создать `site/pereezd.json`: `{"novyj_adres": "https://vitrina-mastera.github.io/"}`.
2. Собрать основной сайт как обычно - все 24 страницы витрин на старом адресе станут переадресациями
   (с сохранением `?...` и `#...`). Скрипты и зашифрованные файлы остаются на месте.
3. PR, слить. Ссылку для клиентов мастеру дать новую; старая тоже работает.
4. Мастеру сказать: на новом адресе один раз заново ввести пин-код.

### 5. Окончательно (позже, не спешим)
- Перенести исходники витрин (`site/vitrina`, `site/vitriny`, `site/krasnodar`, `site/shared` и сборку витрин)
  в новое репо, чтобы оно собиралось само. Тогда основной репозиторий перестаёт их собирать, а переадресации остаются.
- Копия на клиента: отдельный репозиторий в организации на каждого мастера (`vitrina-mastera.github.io/<имя>/`,
  все ссылки относительные - работает) или свой домен на имя клиента.

## Откат

- Шаги 1-3: ничего не меняют на старом сайте. Откат - не давать новую ссылку (или удалить репозиторий).
- Шаг 4: удалить `site/pereezd.json` и собрать сайт заново (или `git revert` коммита переключения) -
  старые страницы витрин возвращаются целиком, ничего не потеряно.

## Что важно знать

- Ключ после ввода пин-кода и черновики Мастерской хранятся в браузере для конкретного адреса. Новый адрес = новый вход.
- Пин-код и токены в репозиторий не попадают; в новом репо, как и в старом, только зашифрованные `enc/`.
- Бесплатный GitHub Pages: только публичный репозиторий, лимит около 1 ГБ на сайт и 100 ГБ трафика в месяц.
  Сейчас витрины весят около 18 МБ.
