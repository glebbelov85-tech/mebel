# Общий формат заказа - версия 1.1

Один заказ - один файл `*.mebel.json`. В нём всё: клиент, изделия с деталями и координатами, материалы, фурнитура, цена, оплаты, этапы. Этот файл одинаково понимают все инструменты проекта: калькулятор его создаёт, конфигуратор меняет отделку, КП и договор из него печатаются, карта раскроя берёт из него детали, учёт заказов хранит его и ведёт оплаты.

## Что лежит в папке

| Файл | Зачем |
|---|---|
| `mebel-order.js` | Общий модуль: создать, проверить, прочитать, сохранить, посчитать. Один файл, без зависимостей |
| `mebel-order.schema.json` | Формальное описание всех полей (JSON Schema 2020-12) |
| `examples/shkaf-kupe.mebel.json` | Пример: шкаф-купе 2400x2600x600, 3 двери, заказ в производстве, есть предоплата и расходы |
| `examples/kuhnya.mebel.json` | Пример: угловая кухня 3000 + 1800, 11 модулей, 121 деталь |
| `examples/staryj-raschet-kalkulyatora.json` | Пример старого сохранения калькулятора - модуль его читает |
| `tools/build-examples.js` | Строит примеры заново |
| `tools/test.js` | 18 проверок модуля на примерах: `node tools/test.js` |

## Быстрый старт

Подключить модуль в HTML-страницу (или вставить содержимое файла целиком в `<script>`):

```html
<script src="mebel-order.js"></script>
<script>
  // новый заказ
  const order = MebelOrder.create({ client: { name: "Айгуль", phone: "+7 701 555 12 34", address: "" } });

  // прочитать файл, который выбрал человек
  const { order: o, report, notes } = await MebelOrder.readFile(input.files[0]);
  if (!report.ok) alert(report.errors.map(e => e.msg).join("\n"));

  // пересчитать цену и сохранить файлом
  MebelOrder.recalc(o);
  MebelOrder.download(o);            // скачает "2026-014-Айгуль.mebel.json"
</script>
```

Главное правило для всех инструментов: **прочитал заказ - поменял только свою часть - вызвал `MebelOrder.touch(order)` - сохранил. Незнакомые поля не удалять.**

## Как устроен заказ

```
заказ
├─ format, version, id, number, title, createdAt, updatedAt, currency "KZT" / "RUB" / ..., country "KZ" / "RU", units "mm"
├─ stage             - текущий этап: lead, measure, design, contract, production, install, done, cancelled
├─ client            - имя, телефон, WhatsApp, адрес установки, ИИН для договора
├─ seller            - реквизиты мастера для КП и договора (необязательно)
├─ products[]        - изделия (в одном заказе может быть кухня и шкаф сразу)
│   ├─ id, type (kupe / kitchen / univ), name, qty, size {w, h, d}
│   ├─ finish        - отделка: роль -> материал. Например { corpus: "ldsp16", facade: "mdf18-film" }
│   ├─ params, generator - по каким параметрам изделие построено (чтобы перестроить)
│   ├─ modules[]     - модули: тумбы кухни, секции и двери шкафа. У модуля свои parts[] и hardware[]
│   ├─ parts[]       - общие детали изделия (корпус шкафа, столешница, цоколь)
│   ├─ hardware[]    - общая фурнитура изделия
│   └─ describe[], image - описание и картинка для клиента (необязательно)
├─ catalog           - материалы, кромка и фурнитура этого заказа с ценами на день расчёта
├─ extras[]          - свои позиции и услуги: доставка, монтаж
├─ pricing           - правила цены: сборка %, наценка %, скидка %, предоплата %, округление
├─ quote             - результат расчёта: строки, себестоимость, итог, предоплата
├─ terms             - срок в днях (рабочих или календарных), гарантия
├─ timeline[]        - этапы с датами: план и факт
├─ payments[]        - оплаты клиента
├─ expenses[]        - расходы по заказу (для настоящей прибыли)
├─ reminders[]       - напоминания
├─ production        - пропил 4 мм, обрезь листа 10 мм, вычитать ли кромку
├─ files[], notes, measure
└─ x                 - служебные данные инструментов (x.calculator, x.tracker и так далее)
```

Все размеры - в миллиметрах. Все деньги - в валюте заказа (`currency`), целыми числами. Даты - в виде `2026-11-14` или `2026-11-14T10:30:00Z`.

## Деталь

Формат детали взят из режима "Любое изделие" калькулятора и немного расширен.

```json
{
  "id": "p7",
  "name": "Полка 1",
  "role": "shelf",
  "mat": "@corpus",
  "o": "Y",
  "x": 16, "y": 400, "z": 3,
  "a": 568, "b": 411,
  "edges": { "front": "@edge" },
  "grain": "a",
  "note": "Подсказка сборщику"
}
```

**Координаты.** X - вправо (ширина), Y - вверх (высота), Z - к себе (глубина). Ноль - левый нижний задний угол. `x, y, z` - это ближний к нулю угол детали.

**Положение `o`** - вдоль какой оси идёт толщина листа:

| `o` | Что это | `a` | `b` | Стороны для кромки |
|---|---|---|---|---|
| `X` | вертикальная боковая (боковина, перегородка) | высота | глубина | front, back, top, bottom |
| `Y` | горизонтальная (полка, дно, крыша, столешница) | ширина | глубина | front, back, left, right |
| `Z` | фронтальная (фасад, задняя стенка, цоколь) | ширина | высота | top, bottom, left, right |

`a` и `b` - размеры **готовой** детали, вместе с кромкой. Толщина берётся из материала.

**Кромка `edges`** задаётся по сторонам понятными словами: "спереди", "сверху". Значение - ключ кромки из каталога (`"pvc04"`) или роль (`"@edge"`). Сторон, которых нет в списке, - без кромки. Так удобно и дизайнеру, и сборщику, а для раскроя модуль сам переводит это в "две длинные и две короткие стороны".

**Текстура `grain`**: `"a"` - рисунок вдоль размера a, `"b"` - вдоль b, `"any"` - не важно. Если не указано: у материала без рисунка - не важно, у материала с рисунком - вдоль большей стороны детали.

**Роль `role`** подсказывает, что это за деталь: side, top, bottom, shelf, partition, back, plinth, facade, drawer, countertop, apron, filler, other. Фасад - это `role: "facade"` (по нему 3D прячет фасады, а фабрике уходит список фасадов). У фасада можно указать `facade: { open: "left" }` - с какой стороны петли (left, right, up, down, drawer, slide, fixed).

**Без координат.** Если деталь пришла списком (например, из спецификации PRO100), координаты можно не указывать, а одинаковые детали записать одной строкой с `qty`. Такая деталь попадёт в распил и цену, но не в 3D.

## Модули

Модуль - это готовый кусок изделия: тумба кухни, секция шкафа, дверь-купе. У него своё положение `pos` и поворот `rot` (0, 90, 180, 270 градусов вокруг вертикальной оси), а детали внутри записаны **от угла самого модуля**. Поэтому модуль можно скопировать или передвинуть, не пересчитывая детали.

```json
{
  "id": "m5", "kind": "lower-drawers3", "name": "Тумба с 3 ящиками 600",
  "pos": { "x": 0, "y": 100, "z": 1180 }, "rot": 90, "wall": "B",
  "size": { "w": 600, "h": 720, "d": 560 },
  "parts": [ ... ], "hardware": [ { "item": "kguide", "qty": 3 } ]
}
```

- `rot: 0` - модуль стоит у задней стены, фасадом к себе.
- `rot: 90` - у левой стены, фасадом вправо. Ширина модуля идёт вдоль Z, и он занимает место от `pos.z - ширина` до `pos.z`.
- `rot: 270` - у правой стены, фасадом влево. Занимает место от `pos.z` до `pos.z + ширина`, а по X - от `pos.x - глубина` до `pos.x`.

Считать повороты руками не нужно: `MebelOrder.partBox(order, product, module, part)` отдаёт готовую коробку детали `{x0, y0, z0, x1, y1, z1}` в координатах изделия.

Дверь-купе - тоже модуль: наполнение (зеркало, ЛДСП) - это деталь, профиль - фурнитура.

## Отделка одним полем

Детали могут ссылаться не на конкретный материал, а на роль: `"mat": "@facade"`. Что стоит за ролью, записано в изделии:

```json
"finish": { "corpus": "ldsp16", "facade": "mdf18-film", "top": "top38", "back": "dvp3", "edge": "pvc04" }
```

Клиент в конфигураторе выбрал другие фасады - меняется одно поле `finish.facade`, и сразу меняются все фасады, цена и список для фабрики. Названия ролей свободные; принятые: corpus, facade, top, back, edge.

Осторожно: если новый материал другой толщины (ЛДСП 16 -> МДФ 18), размеры соседних деталей сами не изменятся. Для фасадов это не страшно, для корпуса изделие лучше перестроить в калькуляторе.

## Каталог

`catalog` - это материалы, кромка и фурнитура, которые нужны именно этому заказу, с ценами на день расчёта. Заказ поэтому самодостаточен: через полгода он откроется с теми же ценами, даже если прайс поменялся.

```json
"materials": {
  "ldsp16": { "name": "ЛДСП 16 мм", "group": "ldsp", "kind": "sheet", "t": 16, "sheet": { "w": 2800, "h": 2070 },
              "grain": true, "decor": "Дуб Сонома", "price": 22000, "cut": true, "color": "#e9d3b5" }
},
"edges":    { "pvc04": { "name": "Кромка ПВХ 0.4 мм", "t": 0.4, "w": 19, "price": 150 } },
"hardware": { "hinge": { "name": "Петля с доводчиком", "unit": "шт", "price": 1200 } }
```

`kind` говорит, как материал считается: `sheet` - листами (ЛДСП, ДВП), `area` - квадратными метрами (фасады МДФ, зеркало), `length` - погонными метрами (столешница). Цена `price` - за лист, за м2 или за метр соответственно.

Строка фурнитуры: `{ "item": "hinge", "qty": 4 }` (берёт название и цену из каталога) или своя: `{ "name": "Навес", "qty": 2, "unit": "шт", "price": 600 }`.

`MebelOrder.defaultCatalog()` - стартовый набор с примерными ценами из калькулятора. Настоящие цены задаёт мастер.

## Цена

`pricing` - правила, `quote` - результат. Правила такие же, как в калькуляторе:

1. Материалы: листовые - целыми листами с учётом использования листа (80%), остальные - по площади или длине. Кромка - с запасом 10%. Распил - за каждый лист. Плюс фурнитура и свои позиции (`extras` с `kind: "item"`).
2. Сборка - процент от материалов.
3. Услуги (`extras` с `kind` delivery, install, service) - доставка, монтаж.
4. Себестоимость = материалы + сборка + услуги. Наценка - процент от себестоимости.
5. Скидка, потом округление итога вверх (`pricing.roundTo`: по умолчанию 1000 тенге или 100 рублей).

`MebelOrder.recalc(order)` считает и записывает `order.quote`:

- `lines` - подробные строки для мастера, `materials`, `work`, `services`, `cost`, `markup`, `profit` - **внутренняя кухня, клиенту не показывать**;
- `clientLines` - строки для клиента: каждое изделие одной суммой, свои позиции, услуги по своей цене;
- `subtotal`, `discountPct`, `discountSum`, `total`, `prepayPct`, `prepaySum` - итоги. Всегда `subtotal - discountSum = total`, а сумма `clientLines` равна `subtotal`.

Остальные инструменты `quote` только читают. Если заказ менялся после расчёта, проверка об этом предупредит.

## Страна и валюта (с версии 1.1)

- `currency` - код валюты ISO 4217. Все суммы заказа (цены каталога, `extras`, оплаты, расходы, `quote`) - в этой одной валюте. Известные модулю: `KZT` (тенге, ₸), `RUB` (рубли, ₽), `BYN`, `UZS`, `KGS`, `USD`, `EUR`. Добавить валюту - одна строка в `CURRENCIES`: знак, три формы слова для сумм прописью ("рубль, рубля, рублей"), шаг округления.
- `country` - страна мастера: `KZ` или `RU`. От неё зависят шаблон договора, реквизиты (БИН/ИИК/Кбе или ИНН/КПП/ОГРН/р/с), способы оплаты (Kaspi или СБП) и ставка НДС по умолчанию. Если поля нет - страна определяется по валюте (тенге - Казахстан, рубли - Россия), заказы версии 1.0 открываются как раньше.
- Настройка "страна и валюта" мастера одна на все инструменты сайта: `MebelOrder.region()` читает её из `localStorage["mebel-region"]` (`{ country, currency }`), `setRegion({ country, currency })` меняет и рассылает событие `mebel-region`. Пока мастер ничего не выбрал, страна угадывается по часовому поясу браузера. Новый заказ (`create()`) берёт валюту и стартовые цены из этой настройки; открытый чужой заказ всегда показывается в своей валюте.
- Помощники: `money(354000, "RUB")` - "354 000 ₽"; `moneyWords(121000, "RUB")` - "сто двадцать одна тысяча рублей"; `currencyWord(n, cur)`, `numWords(n)`, `orderCurrency(order)`, `orderCountry(order)`.
- Курсы валют модуль не знает. `CURRENCIES[...].rateKZT` - очень примерный курс только для стартовых цен; настоящие цены мастер задаёт в своей валюте. Пересчитывать готовый заказ из одной валюты в другую формат не умеет и не должен: цену назначает мастер.

## Прайс поставщика (на будущее)

Чтобы потом подключать прайс магазина или поставщика (файлом или по ссылке), прайс описывается отдельным файлом `*.mebel-price.json`:

```json
{
  "format": "mebel-price", "version": "1.0",
  "currency": "RUB", "country": "RU",
  "supplier": { "name": "Магазин плит", "city": "Москва", "url": "", "phone": "" },
  "date": "2026-11-14",
  "items": [
    { "id": "ldsp16", "sku": "EG-W1000-16", "name": "ЛДСП Egger W1000 16 мм, 2800x2070", "group": "Плиты", "unit": "лист", "price": 4350 },
    { "sku": "BL-71B3550", "name": "Петля Blum Clip top с доводчиком", "group": "Фурнитура", "unit": "шт.", "price": 420 }
  ]
}
```

- `items[].id` - если позиция совпадает с позицией прайса калькулятора (ldsp16, hinge, edge...), цена встаёт на её место; без `id` позиция сверяется по артикулу (`sku`), потом по названию - так же, как при загрузке цен из Excel.
- Калькулятор уже умеет сохранять свой прайс в этом виде и загружать такой файл ("Прайс > Загрузить цены"). Прайсы в разных валютах живут отдельно: у каждой валюты свой.
- Цены в заказ попадают снимком в `catalog` на день расчёта, поэтому смена прайса старые заказы не меняет.

## Оплаты, расходы, этапы

```json
"payments": [ { "id": "pay1", "date": "2026-11-09", "amount": 200000, "kind": "prepay", "method": "kaspi" } ],
"expenses": [ { "id": "exp1", "date": "2026-11-10", "amount": 96500, "category": "materials", "supplier": "База ЛДСП" } ],
"timeline": [ { "stage": "measure", "done": "2026-11-04" }, { "stage": "install", "plan": "2026-12-08" } ],
"reminders": [ { "id": "rem1", "date": "2026-12-01", "text": "Согласовать день монтажа", "done": false } ]
```

`MebelOrder.balance(order)` отдаёт: сколько оплачено, сколько осталось, сколько ещё не хватает до предоплаты, расходы, прибыль по плану и по факту. `setStage(order, "production")` переводит заказ на этап и ставит дату. `nextDue(order)` - ближайшее дело по заказу.

### Список на распил

`cutList(order)` отдаёт по строке на деталь (или по строке на группу одинаковых, если `{ group: true }`):

```json
{
  "id": "p7", "mark": "1-07", "name": "Полка 1",
  "product": { "id": "pr1", "name": "Шкаф-купе" }, "module": { "id": "m1", "name": "Секция 1" },
  "material": { "id": "ldsp16", "name": "ЛДСП 16 мм", "t": 16, "decor": "Дуб Сонома", "sheet": { "w": 2800, "h": 2070 }, "grain": true },
  "length": 778, "width": 497,
  "cutLength": 778, "cutWidth": 497,
  "qty": 1, "grain": "length", "canRotate": false,
  "edges": { "L1": { "id": "pvc04", "name": "Кромка ПВХ 0.4 мм", "t": 0.4 }, "L2": null, "W1": null, "W2": null }
}
```

`length` всегда идёт вдоль текстуры (если она важна). `L1, L2` - кромка на сторонах вдоль длины, `W1, W2` - вдоль ширины. `cutLength, cutWidth` - размер пиления: готовый размер минус кромка толщиной от 1 мм (тонкая 0.4 мм не вычитается). Пропил и обрезь листа лежат в `order.production`.

## Кто что меняет

| Инструмент | Пишет | Читает |
|---|---|---|
| Калькулятор | products, catalog, extras, pricing, quote, terms | всё |
| Конфигуратор | product.finish, client, quote (через recalc), новая заявка со stage "lead" | products, catalog |
| КП и договор | files (ссылка на готовый документ), seller | client, products, quote.clientLines, итоги, terms |
| Карта раскроя | x.cutting (сколько листов вышло на самом деле) | cutList(order), production |
| Учёт заказов | stage, timeline, payments, expenses, reminders, notes | всё |

Свои служебные данные инструмент кладёт в `order.x.<имя инструмента>` и не трогает чужие.

## Как заказ переходит между инструментами

1. **Файл** `*.mebel.json` - основной способ: "Сохранить заказ" в одном инструменте, "Открыть заказ" в другом. Работает всегда, удобно хранить и пересылать.
2. **Ссылка** - `toLink(order, адрес страницы)` прячет сжатый заказ в хвост адреса. Кухня из 121 детали - это ссылка примерно в 6400 знаков. Удобно отправить клиенту в WhatsApp ссылку на конфигуратор уже с его кухней. Клиенту отправлять копию `forClient(order)`.
3. **Буфер обмена** - `stringify(order)` и `parse(text)`: скопировал в одном окне, вставил в другом.

## Версии

- `version: "1.1"` (1.1 добавила `country` и разрешила любую валюту вместо только тенге). Первая цифра меняется, только если старые файлы перестают читаться как есть, - тогда в `migrate()` добавляется шаг перевода, и старые файлы открываются автоматически.
- Вторая цифра (1.1, 1.2) - добавились необязательные поля. Инструмент версии 1.0 такой файл читает, незнакомое просто сохраняет.
- Файл из более новой первой цифры модуль не откроет и попросит обновить инструмент.
- Старые расчёты калькулятора (то, что лежит в "Сохранённых") `migrate()` уже понимает: "Любое изделие" переносится полностью с деталями, "Купе" и "Кухня" - параметрами и ценой, пока калькулятор не перейдёт на общий движок деталей. Свои цены передаются так: `migrate(obj, { prices: JSON.parse(localStorage.kupe_prices) })`.

## Откуда идеи

Чужие программы не копировали, взяли только принятые в отрасли подходы:

- Из списков на распил (CutList Optimizer, MaxCut, OptiCut, раскрой в Базисе): у детали длина, ширина, количество, направление текстуры и кромка отдельно по каждой из четырёх сторон; готовый размер и размер пиления различаются.
- Из PRO100 и Базис-Мебельщика: изделие собирается из блоков (у нас модули) со своими координатами; спецификация - это плоский список деталей с материалом и кромкой.
- Из K3 и кухонных конфигураторов: отделка задаётся отдельно от геометрии - поэтому роли `@corpus`, `@facade`.
- Своё: кромка словами "спереди, сверху", подсказки сборщику прямо в детали, заказ целиком в ссылке, копия для клиента без себестоимости, цены внутри заказа.

## Готовые библиотеки, которые стоит взять

Сам формат зависимостей не требует. Для инструментов вокруг него пригодятся (версии проверять при подключении):

- **Ajv** - проверка по `mebel-order.schema.json`, если нужна строгая проверка каждого поля. В обычной работе хватает `MebelOrder.validate`.
- **maxrects-packer** или свой guillotine-алгоритм - раскладка деталей на листе; вход - `cutList(order)`.
- **pdfmake** - КП и договор в PDF; его стандартный шрифт Roboto умеет кириллицу.
- **SheetJS** - прайсы поставщиков из Excel в `catalog`.
- **three.js** - 3D; коробки деталей даёт `partBox`.

## Что отложено на следующие версии

- Присадка: отверстия, пазы, вырезы с точными координатами. Сейчас это `ops` и `note` в свободной форме.
- Подробный замер помещения (стены, окна, трубы) - сейчас свободный раздел `measure`.
- Общий прайс мастера отдельным файлом - сейчас цены живут в `catalog` каждого заказа.
- Импорт спецификации из программы дяди - когда станет известно, какая это программа и что она выгружает.
